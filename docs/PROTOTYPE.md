# ใช้งาน Prototype บนเครื่อง

## เริ่มเดโม

ติดตั้ง dependency ตาม README ก่อน จากโฟลเดอร์โปรเจกต์รัน:

```powershell
node scripts/start-demo.mjs
```

เปิด http://127.0.0.1:3001/demo เพื่ออ่านขั้นตอนและบัญชีทดลอง API อยู่ที่ 127.0.0.1:4001 เดโมใช้ MongoDB ชั่วคราวของตัวเองบน loopback และฐานข้อมูล `zonify_demo` ไม่ต้องเปิด MongoDB ของโปรเจกต์เดิม หากยังไม่มี MongoDB binary ใน cache การเริ่มครั้งแรกต้องใช้อินเทอร์เน็ตเพื่อดาวน์โหลดผ่าน mongodb-memory-server

รหัสผ่านทุกบัญชี: `ZonifyDemo2026!`

| บทบาท | อีเมล |
| --- | --- |
| ผู้เช่า | customer@demo.zonify.test |
| ผู้จัดการ | manager@demo.zonify.test |
| เจ้าของ | owner@demo.zonify.test |

เปิดคนละ browser profile หรือหน้าต่างส่วนตัวสำหรับผู้เช่าและผู้จัดการ เพราะทุกแท็บใน profile เดียวกันใช้ session ร่วมกัน บัญชีผู้เช่ามีร้านเดโมและรายการวันพรุ่งนี้ 4 สถานะ: พักล็อก รอชำระ รอตรวจสลิป และยืนยันแล้ว วันที่อ้างอิงเวลาไทยเมื่อเริ่ม/รีเซ็ต เวลาพักล็อกและรอชำระนับถอยหลังจริงและหมดอายุได้

## เส้นทางสาธิต

1. สมัครบัญชีใหม่และเข้าสู่ระบบ หรือใช้บัญชีผู้เช่า
2. เปิดร้านของฉัน เพิ่มร้านในตลาดริมคลอง หรือใช้ร้านเดโมที่เตรียมไว้
3. เลือกตลาด วัน และล็อกว่าง จากนั้นเลือกร้าน พักล็อก และดำเนินการชำระเงิน
4. เปิด QR แล้วกด **สร้างและส่งสลิปจำลอง** QR เป็นข้อความ `ZONIFY-DEMO:…:NO-PAYMENT` ไม่มีข้อมูลพร้อมเพย์ ใช้โอนเงินผ่านธนาคารไม่ได้
5. ผู้จัดการเปิดหลังบ้าน หน้าตั้งต้นเป็น **งานที่ต้องดำเนินการ** เปิดตรวจชำระเงิน แล้วปฏิเสธหลักฐานพร้อมเหตุผล
6. ผู้เช่าส่งหลักฐานจำลองใหม่ ผู้จัดการตรวจข้อมูลจำลองและอนุมัติ ผู้เช่าจะเห็นสถานะยืนยันแล้ว
7. ดูตำแหน่งร้านในวันที่จอง หรือทดลองยกเลิกและบันทึกคืนเงินจำลองด้วยบัญชีผู้จัดการ

ป้ายโหมดเดโมแสดงทุกหน้า รายงาน ยอดเงิน การอนุมัติและคืนเงินทั้งหมดเป็นข้อมูลสมมติ ไม่มีการติดต่อธนาคาร ปุ่มจำลองใช้กฎสิทธิ์ การถือครองรายการ เวลาหมดอายุ จำนวนครั้ง และการตรวจสลิปชุดเดียวกับ flow ปกติ

## รีเซ็ต

ขณะเดโมเปิดอยู่ ใช้ terminal อีกหน้าต่างในโฟลเดอร์โปรเจกต์:

```powershell
node scripts/reset-demo.mjs
```

คำสั่งเข้าสู่ระบบด้วยบัญชีเจ้าของเดโม แล้วเรียก reset เฉพาะโปรไฟล์นี้ ข้อมูลที่กรอกเพิ่มจะถูกลบและสร้างตัวอย่างใหม่ Session ทุกบัญชีถูกยกเลิก ให้ refresh และเข้าสู่ระบบใหม่ หากเปลี่ยนรหัสผ่านเจ้าของเดโมจนคำสั่งใช้ไม่ได้ ให้หยุดเดโมด้วย Ctrl+C แล้วเริ่มใหม่

Ctrl+C ใน terminal ที่เปิดเดโมจะหยุด frontend/backend ที่คำสั่งนี้สร้าง การเริ่มรอบใหม่สร้างฐานข้อมูลชั่วคราวใหม่ คำสั่งไม่เริ่มหากพอร์ต 3001 หรือ 4001 มีบริการอื่นใช้งานอยู่

## API และค่าตั้งค่า

- `ZONIFY_DEMO_MODE=1` กำหนดโดย launcher ให้ทั้ง frontend/backend; backend ยอมรับเฉพาะ MongoDB แบบ loopback ฐาน `zonify_demo`, HTTP origin และ backend host แบบ loopback โปรไฟล์เดิมไม่ได้เปิดโหมดนี้โดยอัตโนมัติ
- `POST /api/bookings/:id/payment/demo-slip` รับ `{}` เฉพาะโหมดเดโม ต้องเป็นเจ้าของรายการ เปิด QR แล้ว และยังอยู่ในเวลาชำระ ตอบ 201 เป็น booking รอตรวจสลิป ปิดโหมดแล้วตอบ 404
- `POST /api/demo/reset` ใช้ session เจ้าของและ Origin ที่ถูกต้อง ปิดรับคำขอใหม่ระหว่างรีเซ็ต และรอคำขอ/worker เดิมจบก่อนล้างข้อมูล ปิดโหมดแล้วตอบ 404
- QR response เพิ่ม `simulated: boolean`; booking เพิ่ม `payment.simulated: boolean`
- Client JSON requests มี deadline 10–15 วินาทีรวม response body; server reads ที่เกี่ยวข้องมี deadline 5 วินาที คำขอเขียนที่ timeout ไม่ถูกส่งซ้ำอัตโนมัติ ข้อความจะแนะนำให้โหลดข้อมูลล่าสุดก่อนส่งใหม่
- ฟอนต์ Noto Sans Thai อยู่ในโปรเจกต์พร้อม OFL ที่ `frontend/app/fonts` ไม่ต้องติดต่อ Google Fonts ระหว่าง build

## ตรวจซ้ำ

จาก backend ใช้ `pnpm test` และ `pnpm exec tsc --noEmit` จาก frontend ใช้ `pnpm test`, `pnpm lint` และ `pnpm build`

เปิดเดโมก่อนรัน `node scripts/demo-browser.mjs` จาก root ต้องมี Playwright และ Chrome ใช้ `QA_PLAYWRIGHT_MODULE` ชี้ไปที่ Playwright `index.mjs` ที่ติดตั้งแล้วหากไม่มี module ที่ root; `QA_OUTPUT` กำหนดโฟลเดอร์ภาพ/ผลตรวจ ค่าเริ่มต้นอยู่ใน temp ของเครื่อง สคริปต์สร้างบัญชีและร้านในฐานเดโมเท่านั้น

ไม่มีการ deploy หรือทดสอบรับเงินจริงในงานนี้

ผลตรวจวันที่ 20 ตุลาคม 2026: backend 97/97, frontend 8/8, lint และ typecheck ผ่าน, production build ผ่านโดยไม่ใช้ Google Fonts. Browser plugin ไม่พร้อมใช้งาน จึงใช้ Chrome กับ bundled Playwright ทดสอบ register → shop → hold → demo QR/slip → reject → resubmit → approve ครบทั้ง 1440px และ 390px รวม competing hold, published location, reset และฟอร์มคงข้อมูลหลัง save timeout. ไม่มี application runtime errors; Chrome บน Next dev มีคำเตือน CSS preload ที่ยังไม่ถูกใช้งานหลังเปลี่ยน route ซึ่งบันทึกแยกในผล QA. ใช้ QA_VIEWPORT_WIDTH=390 เพื่อรัน flow เต็มบนมือถือ.
